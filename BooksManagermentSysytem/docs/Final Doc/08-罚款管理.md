## 1. 罚款规则体系

### 1.1 罚款类型

#### 1.1.1 逾期罚款

**触发条件**：图书未按期归还

**计算公式**：
```
逾期罚款 = 书籍价格 × 逾期价格系数 + 逾期天数 × 逾期日系数 + 免罚天数抵扣
```

**示例**（本校学生）：
- 书籍价格：¥39.80
- 逾期3天
- 逾期价格系数：10%（0.1）
- 逾期日系数：¥0.1/天
- 免罚天数：0天

计算：39.80 × 0.1 + 3 × 0.1 = 3.98 + 0.3 = ¥4.28

#### 1.1.2 破损赔偿

**触发条件**：归还时图书有破损

**赔偿标准**：

| 破损程度 | 赔偿系数 | 说明 |
|---------|---------|------|
| 轻微破损 | 25% | 页角折、轻微污渍等 |
| 严重破损 | 50% | 书脊脱胶、页面缺损等 |

**示例**：
- 图书价格：¥88.00
- 严重破损：88.00 × 50% = ¥44.00

#### 1.1.3 丢失赔偿

**触发条件**：图书丢失

**赔偿标准**：100%图书价格

**示例**：
- 图书价格：¥39.80
- 丢失赔偿：¥39.80

## 2. 罚款计算过程

### 2.1 自动计算流程

```
图书归还
    ↓
检查应还日期 vs 实际还日期
    ├─ 未逾期 → 检查物理状态
    └─ 已逾期 → 计算逾期天数
    ↓
根据物理状态计算罚款
    ├─ 完好 → 逾期罚款（仅逾期）
    ├─ 轻微破损 → max(逾期罚款, 破损赔偿)
    └─ 严重破损/丢失 → max(逾期罚款, 破损赔偿)
    ↓
应用最大罚款限制
    └─ 罚款金额 = min(计算值, 最大罚款)
    ↓
存储罚款记录
    ├─ 罚款原因
    ├─ 罚款金额
    └─ 支付状态（未支付）
```

### 2.2 计算存储过程

```sql
CREATE PROCEDURE sp_calculate_fine
    @bookID NVARCHAR(30),
    @fineType NVARCHAR(20),
    @overdueDays INT = 0,
    @fineAmount DECIMAL(10,2) OUTPUT
AS
BEGIN
    DECLARE @bookPrice DECIMAL(10,2)
    DECLARE @readerType NVARCHAR(20)
    DECLARE @overdue_price_rate DECIMAL(5,4)
    DECLARE @overdue_day_rate DECIMAL(5,2)
    DECLARE @max_fine DECIMAL(10,2)
    
    -- 查询罚款规则
    SELECT @readerType = r.readertype
    FROM ... (通过bookID反向查询)
    
    SELECT @overdue_price_rate = fr.overdue_price_rate,
           @overdue_day_rate = fr.overdue_day_rate,
           @max_fine = fr.max_overdue_fine
    FROM FINE_RULES fr
    WHERE fr.reader_type = @readerType
    
    -- 计算罚款
    SET @fineAmount = CASE @fineType
        WHEN 'OVERDUE' THEN @bookPrice * @overdue_price_rate + @overdueDays * @overdue_day_rate
        WHEN 'DAMAGED' THEN @bookPrice * 0.5
        WHEN 'LOST' THEN @bookPrice
        ELSE 0
    END
    
    -- 应用最大罚款限制
    IF @fineAmount > @max_fine AND @max_fine IS NOT NULL
        SET @fineAmount = @max_fine
END
```

## 6. 罚款统计与报表

### 6.1 罚款总额统计

```sql
SELECT 
    SUM(amount) AS 总罚款,
    SUM(CASE WHEN fine_status='已支付' THEN amount ELSE 0 END) AS 已收取,
    SUM(CASE WHEN fine_status='未支付' THEN amount ELSE 0 END) AS 未收取
FROM fine
WHERE created_time >= @startDate 
    AND created_time < @endDate
```

### 6.2 按罚款原因统计

```sql
SELECT TOP 10
    reason,
    COUNT(*) AS 发生次数,
    SUM(amount) AS 总金额,
    AVG(amount) AS 平均金额
FROM fine
GROUP BY reason
ORDER BY 总金额 DESC
```

### 6.3 按读者类型统计

```sql
SELECT 
    r.readertype,
    COUNT(f.fine_id) AS 罚款次数,
    SUM(f.amount) AS 总罚款,
    SUM(CASE WHEN f.fine_status='未支付' THEN f.amount ELSE 0 END) AS 未支付
FROM fine f
INNER JOIN reader r ON f.cardID = r.cardID
GROUP BY r.readertype
```

## 7. 罚款对读者权限的影响

### 7.1 有罚款时的限制

```
检查是否有未支付罚款
    ├─ 若无：正常借阅
    └─ 若有：发出警告但仍允许借阅
```

**建议**：系统不禁止有罚款的读者借书，但应：
- 在界面醒目提示
- 鼓励读者支付
- 提供支付便利

### 7.2 额外限制（可选）

如果需要更严格的规则，可配置：

```
FINE_RULES表新增字段
├─ block_borrow_if_fine: 是否因罚款禁借
├─ block_renew_if_fine: 是否因罚款禁续借
└─ block_reserve_if_fine: 是否因罚款禁预约
```

## 8. 常见问题

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| 罚款金额过高 | 逾期时间长 | 及时归还或赔偿 |

## 9. 最佳实践

### 9.1 罚款政策建议

1. **合理设置免罚天数**
   - 考虑天气、假期等因素
   - 教师可适当延长

2. **最大罚款限制**
   - 防止罚款过高
   - 保护读者权益

3. **透明收费**
   - 明确公示罚款规则
   - 提供详细说明

### 9.2 运维建议

1. **定期检查**
   - 监控未支付罚款
   - 定期催缴

2. **异常处理**
   - 发现计算错误及时更正
   - 特殊情况人工审批

3. **数据统计**
   - 定期生成统计报表
   - 分析罚款原因
