## 2. 部署流程

### 2.1 环境准备

#### 2.1.1 检查系统

```cmd
# 查看.NET Framework版本
HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\NET Framework Setup\NDP\v4\Full

# 检查SQL Server
sqlcmd -S localhost -U sa -P password -Q "SELECT @@VERSION"

# 检查网络连接
ping database-server-ip
```

#### 2.1.2 创建用户和权限

```sql
-- 为SQL Server创建应用用户
USE master
CREATE LOGIN [AppUser] WITH PASSWORD = 'StrongPassword123!';

-- 创建数据库
CREATE DATABASE LibraryDB
    ON PRIMARY
    (NAME = LibraryDB_data, 
     FILENAME = 'D:\Data\LibraryDB_data.mdf'),
    LOG ON
    (NAME = LibraryDB_log, 
     FILENAME = 'D:\Data\LibraryDB_log.ldf');

-- 创建数据库用户
USE LibraryDB
CREATE USER [AppUser] FOR LOGIN [AppUser];
ALTER ROLE db_owner ADD MEMBER [AppUser];
```

### 2.2 数据库部署

#### 2.2.1 执行初始化脚本

部署脚本执行顺序：

```
1. database.sql                    -- 核心表和数据
2. schema_extensions.sql           -- 扩展表
3. permission_system.sql           -- 权限系统
4. create_rules_tables.sql         -- 规则表
5. init_rules_data.sql             -- 规则初始数据
6. renew_reservation_extensions.sql -- 扩展功能
```

**执行方式**：

```cmd
# 使用SQL Server Management Studio
# 或使用命令行
sqlcmd -S localhost -U AppUser -P Password -d LibraryDB -i database.sql
sqlcmd -S localhost -U AppUser -P Password -d LibraryDB -i schema_extensions.sql
...
```

#### 2.2.2 验证数据库

```sql
-- 检查表是否创建成功
SELECT COUNT(*) FROM INFORMATION_SCHEMA.TABLES 
WHERE TABLE_SCHEMA = 'dbo'

-- 检查数据完整性
SELECT COUNT(*) FROM BOOK_CATEGORY
SELECT COUNT(*) FROM app_user
SELECT COUNT(*) FROM BORROW_RULES
```

## 3. 运维指南

### 3.1 日常运维任务

#### 3.1.1 每日检查清单

```
□ 检查系统日志，查看是否有错误
  位置：应用程序事件查看器
  
□ 验证SQL Server是否正常运行
  sqlcmd -S localhost -U sa -P password -Q "SELECT GETDATE()"
  
□ 检查磁盘空间
  C:\drive: 保证至少10GB可用空间
  
□ 验证备份是否完成
  最新备份时间是否在24小时内
```

#### 3.1.2 周期性维护

**每周**：
```sql
-- 重建碎片化索引
ALTER INDEX ALL ON dbo.bookborrow REBUILD

-- 更新统计信息
UPDATE STATISTICS dbo.BOOK_ITEM
```

**每月**：
```sql
-- 完整数据库检查
DBCC CHECKDB (LibraryDB)

-- 查看索引使用情况
SELECT TOP 10 OBJECT_NAME(ips.object_id) AS TableName,
              i.name AS IndexName,
              ips.user_seeks,
              ips.user_scans
FROM sys.dm_db_index_usage_stats ips
INNER JOIN sys.indexes i ON ips.object_id = i.object_id
ORDER BY (ips.user_seeks + ips.user_scans) DESC
```

**每季度**：
```
□ 备份数据库完整副本到异地
□ 验证恢复过程可行性
□ 更新系统文档
□ 进行容量规划评估
```

### 3.2 性能优化

#### 3.2.1 查询性能

```sql
-- 查找慢查询
SELECT TOP 20 
    qs.execution_count,
    qs.total_elapsed_time/1000000 AS total_elapsed_time_sec,
    qs.last_elapsed_time/1000 AS last_elapsed_time_ms,
    qt.text AS query_text
FROM sys.dm_exec_query_stats qs
CROSS APPLY sys.dm_exec_sql_text(qs.sql_handle) qt
ORDER BY qs.total_elapsed_time DESC
```

#### 3.2.2 索引优化

```sql
-- 找出未使用的索引
SELECT OBJECT_NAME(i.object_id) AS TableName,
       i.name AS IndexName
FROM sys.indexes i
LEFT JOIN sys.dm_db_index_usage_stats ius
    ON i.object_id = ius.object_id
    AND i.index_id = ius.index_id
WHERE OBJECTPROPERTY(i.object_id, 'IsUserTable') = 1
    AND ius.index_id IS NULL
    AND i.index_id > 0
```

#### 3.2.3 缓存优化

```csharp
// 使用缓存减少数据库查询
private static readonly Dictionary<string, object> _cache = new Dictionary<string, object>();
private static readonly object _lockObject = new object();

public BorrowRules GetBorrowRuleFromCache(string readerType)
{
    lock (_lockObject)
    {
        string key = $"BorrowRule_{readerType}";
        
        if (!_cache.ContainsKey(key))
        {
            _cache[key] = GetBorrowRuleFromDB(readerType);
        }
        
        return (BorrowRules)_cache[key];
    }
}
```

## 4. 故障排查

### 4.1 常见问题

#### 4.1.1 应用无法启动

**症状**：点击exe文件无反应或闪退

**排查步骤**：
```
1. 检查.NET Framework版本
   powershell: (Get-ItemProperty "HKLM:\SOFTWARE\Microsoft\NET Framework Setup\NDP\v4\Full").Release
   应输出的值：394802 或更高（.NET Framework 4.8）
   
2. 查看事件查看器错误日志
   开始 → 事件查看器 → Windows日志 → 应用程序
   
3. 检查配置文件
   确保App.config中的connectionString正确
   
4. 验证SQL Server连接
   sqlcmd -S localhost -U AppUser -P Password -d LibraryDB
```

#### 4.1.2 数据库连接失败

**症状**：操作时出现"Cannot open database connection"错误

**原因与解决**：

| 错误信息 | 原因 | 解决 |
|---------|------|------|
| Login failed | 用户名密码错误 | 核对credentials |
| Database does not exist | 数据库未创建 | 运行初始化脚本 |
| Connection timeout | SQL Server未运行 | 启动SQL Server服务 |
| Network error | 网络不可达 | 检查防火墙和网络 |

#### 4.1.3 查询超时

**症状**：某些查询执行缓慢或超时

**解决方案**：

```sql
-- 1. 查看查询执行计划
SET STATISTICS IO ON
SELECT * FROM reader WHERE cardID = 'BRW-2025-1-000001'

-- 2. 检查索引是否有效
DBCC SHOW_STATISTICS (reader, IX_reader_type)

-- 3. 重建索引
ALTER INDEX ALL ON reader REBUILD

-- 4. 更新统计
UPDATE STATISTICS reader
```

#### 4.1.4 磁盘空间不足

**症状**：收到磁盘空间不足警告

**解决步骤**：

```
1. 确定大文件位置
   dir C:\ /s | sort /r
   
2. 清理日志文件
   SqlServer: truncate log LibraryDB with no_log
   
3. 扩展磁盘空间
   添加新硬盘或扩展分区
   
4. 配置自动清理
   定期删除旧日志和备份
```

### 4.2 性能问题诊断

#### 4.2.1 高CPU占用

```
1. 启动任务管理器，找出占用CPU的进程
2. 如果是SQL Server，运行：
   SELECT * FROM sys.processes
3. 终止长时间运行的查询
4. 优化该查询的执行计划
```

#### 4.2.2 内存溢出

```
1. 检查进程内存使用
   任务管理器 → 性能 → 内存
   
2. 如果是应用程序
   重启应用
   检查是否有内存泄漏
   
3. 如果是SQL Server
   检查缓冲池大小
   优化查询以使用更少内存
```

## 5. 备份与恢复

### 5.1 备份策略

#### 5.1.1 备份计划

```
完整备份：每周日晚23:00
差分备份：每日晚23:00
事务日志：每4小时

备份位置：D:\Backups\
保留期：
- 完整备份：保留4周
- 差分备份：保留1周
- 日志：保留7天
```

#### 5.1.2 备份脚本

```sql
-- 完整备份
BACKUP DATABASE LibraryDB 
TO DISK = 'D:\Backups\LibraryDB_full.bak'
WITH INIT, COMPRESSION, 
     DESCRIPTION = 'Full backup';

-- 差分备份
BACKUP DATABASE LibraryDB 
TO DISK = 'D:\Backups\LibraryDB_diff.bak'
WITH DIFFERENTIAL, COMPRESSION,
     DESCRIPTION = 'Differential backup';

-- 事务日志备份
BACKUP LOG LibraryDB
TO DISK = 'D:\Backups\LibraryDB_log.bak'
WITH COMPRESSION,
     DESCRIPTION = 'Log backup';
```

#### 5.1.3 自动备份配置

```
SQL Server Agent → New Job
  名称：LibraryDB_Daily_Backup
  步骤：执行上述SQL脚本
  计划：每天23:00
  失败处理：重试3次
```

### 5.2 恢复流程

#### 5.2.1 完全恢复

```sql
-- 1. 设置数据库为单用户模式
ALTER DATABASE LibraryDB
SET SINGLE_USER WITH ROLLBACK IMMEDIATE

-- 2. 恢复完整备份
RESTORE DATABASE LibraryDB
FROM DISK = 'D:\Backups\LibraryDB_full.bak'
WITH NORECOVERY

-- 3. 恢复差分备份（如有）
RESTORE DATABASE LibraryDB
FROM DISK = 'D:\Backups\LibraryDB_diff.bak'
WITH NORECOVERY

-- 4. 恢复日志
RESTORE LOG LibraryDB
FROM DISK = 'D:\Backups\LibraryDB_log.bak'
WITH RECOVERY

-- 5. 恢复多用户模式
ALTER DATABASE LibraryDB
SET MULTI_USER
```

#### 5.2.2 恢复验证

```sql
-- 检查数据完整性
DBCC CHECKDB (LibraryDB)

-- 检查关键表
SELECT COUNT(*) FROM reader
SELECT COUNT(*) FROM BOOK_ITEM
SELECT COUNT(*) FROM bookborrow

-- 测试存储过程
EXEC sp_GetBorrowRuleByReaderType @reader_type = N'本校学生'
```

## 7. 升级和维护

### 7.1 系统升级

```
升级流程：
1. 备份现有系统和数据库
2. 在测试环境进行升级验证
3. 制定升级计划和回滚方案
4. 通知所有用户升级维护时间
5. 停止应用和相关服务
6. 执行升级脚本
7. 数据迁移和验证
8. 启动应用和服务
9. 验证功能正常
10. 恢复用户访问
```

### 7.2 补丁管理

```
补丁应用流程：
1. 在测试环境验证补丁
2. 评估补丁对系统的影响
3. 制定应用计划（在维护窗口）
4. 备份系统
5. 应用补丁
6. 验证系统状态
7. 如出现问题，执行回滚
```
