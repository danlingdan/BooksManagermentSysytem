# 功能权限精细化管理与批量角色分配功能说明

## 功能概述

本文档说明图书管理系统新增的两个核心权限管理功能：
1. **功能权限精细化管理**（PermissionManagementControl）
2. **批量角色分配**（BatchRoleAssignmentControl）

这两个功能实现了细粒度的权限控制和高效的用户角色批量管理。

---

## 一、功能权限精细化管理

### 1.1 功能简介

将系统操作功能拆解为独立的权限项（如"图书编目"、"读者信息修改"、"借阅规则设置"等），支持权限项与角色的灵活关联，实现细粒度的权限控制。

### 1.2 权限体系设计

#### 权限分组
权限按业务模块分为以下几组：

| 权限分组 | 说明 | 包含权限数 |
|---------|------|-----------|
| 图书管理 | 图书编目、馆藏、分类、库位管理 | 5 |
| 读者服务 | 读者信息、借书证、借阅、续借、预约 | 6 |
| 规则配置 | 借阅规则、处罚规则、罚款管理 | 3 |
| 系统管理 | 用户管理、权限管理、日志、配置 | 4 |
| 统计分析 | 借阅、读者、图书统计报表 | 3 |

#### 权限项详细列表

**图书管理类权限：**
- `BOOK_CATALOG` - 图书编目：创建和编辑书目信息
- `BOOK_CATALOG_DELETE` - 删除书目：删除书目记录
- `BOOK_ITEM_MANAGE` - 馆藏管理：管理馆藏实体，包括新增、下架等
- `BOOK_CATEGORY_MANAGE` - 分类管理：管理图书分类体系
- `BOOK_LOCATION_MANAGE` - 库位管理：管理图书库位信息

**读者服务类权限：**
- `READER_INFO_VIEW` - 读者信息查看：查看读者基本信息
- `READER_INFO_MODIFY` - 读者信息修改：修改读者基本信息
- `READER_CARD_MANAGE` - 借书证管理：管理借书证的办理、挂失、补办等
- `BORROW_OPERATION` - 借阅操作：办理图书借阅和归还
- `BORROW_RENEW` - 续借操作：办理图书续借
- `RESERVATION_MANAGE` - 预约管理：管理图书预约

**规则配置类权限：**
- `BORROW_RULE_SETTING` - 借阅规则设置：配置借阅规则参数
- `FINE_RULE_SETTING` - 处罚规则设置：配置处罚规则参数
- `FINE_MANAGE` - 罚款管理：管理罚款记录和缴费

**系统管理类权限：**
- `USER_MANAGE` - 用户管理：管理系统用户账户
- `ROLE_PERMISSION_MANAGE` - 角色权限管理：配置角色权限关系
- `SYSTEM_LOG_VIEW` - 系统日志查看：查看系统操作日志
- `SYSTEM_CONFIG` - 系统配置：修改系统配置参数

**统计分析类权限：**
- `REPORT_BORROW_STATS` - 借阅统计报表：查看借阅统计数据
- `REPORT_READER_STATS` - 读者统计报表：查看读者统计数据
- `REPORT_BOOK_STATS` - 图书统计报表：查看图书统计数据

### 1.3 默认角色权限配置

#### Admin（系统管理员）
- **权限范围**：所有权限（21项）
- **特点**：权限不可修改，始终拥有全部权限

#### Cataloger（图书采编员）
- **图书管理**：图书编目、删除书目、馆藏管理、分类管理、库位管理
- **读者服务**：读者信息查看
- **统计分析**：图书统计报表
- **合计**：7项权限

#### Librarian（图书管理员）
- **读者服务**：读者信息查看、读者信息修改、借书证管理、借阅操作、续借操作、预约管理
- **规则配置**：罚款管理
- **统计分析**：借阅统计报表、读者统计报表
- **合计**：9项权限

#### Reader（读者）
- **读者服务**：读者信息查看
- **合计**：1项权限

### 1.4 数据库设计

#### 权限表（sys_permission）
```sql
CREATE TABLE sys_permission (
    permission_id INT IDENTITY(1,1) PRIMARY KEY,
    permission_code NVARCHAR(50) NOT NULL UNIQUE,    -- 权限代码
    permission_name NVARCHAR(100) NOT NULL,          -- 权限名称
    permission_group NVARCHAR(50) NOT NULL,          -- 权限分组
    description NVARCHAR(500) NULL,                  -- 权限说明
    is_active BIT NOT NULL DEFAULT(1),               -- 是否启用
    created_time DATETIME2(0) NOT NULL,
    updated_time DATETIME2(0) NULL
);
```

#### 角色权限关联表（sys_role_permission）
```sql
CREATE TABLE sys_role_permission (
    role_permission_id INT IDENTITY(1,1) PRIMARY KEY,
    role_name NVARCHAR(20) NOT NULL,                 -- 角色名称
    permission_code NVARCHAR(50) NOT NULL,           -- 权限代码
    granted_by NVARCHAR(50) NULL,                    -- 授权人
    granted_time DATETIME2(0) NOT NULL,
    CONSTRAINT uq_role_permission UNIQUE(role_name, permission_code)
);
```

## 二、批量角色分配功能

### 2.1 功能简介

支持一次性为多名用户分配相同角色，提升批量用户管理效率。适用于新员工入职、部门调整、角色变更等场景。

### 2.2 界面说明

#### 布局结构
```
┌───────────────────────────────────────────────────────┐
│ 批量角色分配                                           │
│ 目标角色: [图书管理员▼]              [批量分配角色]    │
├─────────────────┬─────────┬─────────────────────────┤
│ 可选用户 (共5人) │         │ 已选用户 (共3人)         │
│ ┌─────────────┐ │ 全部添加>>│ ┌─────────────────────┐ │
│ │搜索: [____] │ │   添加> │ │ 用户名│显示名│当前角色│ │
│ │角色: [全部▼]│ │        │ │ lib01│张三  │读者    │ │
│ │   [搜索]    │ │ <移除  │ │ lib02│李四  │读者    │ │
│ ├─────────────┤ │<<全部移除│ │ lib03│王五  │采编员  │ │
│ │用户名│显示名│ │        │ └─────────────────────┘ │

└───────────────────────────────────────────────────────┘
```

#### 操作流程
1. 在顶部选择"目标角色"
2. 在左侧筛选并选择用户（支持搜索和角色筛选）
3. 通过中间按钮将用户添加到右侧"已选用户"列表
4. 点击"批量分配角色"按钮
5. 系统批量更新用户角色

### 2.3 功能特性

#### 用户筛选
- **关键字搜索**：按用户名或显示名称模糊搜索
- **角色筛选**：筛选特定角色的用户
- **实时过滤**：已选用户不在可选列表中显示

#### 批量操作
- **单个添加**：选中单个或多个用户，点击"添加 >"
- **全部添加**：点击"全部添加 >>"，一次性添加所有可选用户
- **单个移除**：选中已选用户，点击"< 移除"
- **全部移除**：点击"<< 全部移除"，清空已选列表

#### 分配确认
- 显示待分配用户数量
- 二次确认对话框
- 显示成功/失败统计

### 2.4 使用场景

#### 场景1：新员工批量入职
**情况**：图书馆新招聘5名图书管理员

1. 管理员登录系统
2. 进入"系统管理" → "批量角色分配"
3. 目标角色选择"图书管理员"
4. 在左侧筛选当前角色为"读者"的用户
5. 选中5名新员工账户
6. 点击"添加 >"
7. 点击"批量分配角色"
8. 系统一次性将5人角色设为图书管理员

#### 场景2：部门调整
**情况**：3名图书管理员调整为采编员

1. 目标角色选择"图书采编员"
2. 左侧角色筛选选择"图书管理员"
3. 选中需要调整的3人
4. 添加到已选列表
5. 批量分配角色

#### 场景3：临时权限回收
**情况**：活动结束后，批量回收临时管理权限

1. 目标角色选择"读者"
2. 搜索临时账户关键字
3. 全部添加到已选列表
4. 批量分配为读者角色

## 四、安全特性

### 4.1 权限隔离
- **Admin角色保护**：系统管理员权限不可修改
- **自我保护**：用户不能删除自己的账户
- **权限检查**：所有敏感操作前都进行权限验证

### 4.2 数据完整性
- **外键约束**：角色权限关联表引用权限表
- **唯一约束**：同一角色不能重复授予相同权限
- **级联删除**：删除权限时自动清理关联数据

### 4.3 操作审计
- **授权记录**：记录授权人和授权时间
- **变更日志**：建议在catalog_log表中记录权限变更
- **批量跟踪**：批量分配记录操作人和受影响用户数

## 五、最佳实践

### 5.1 权限配置原则
1. **最小权限原则**：只授予必需的权限
2. **职责分离**：避免一个角色拥有过多权限
3. **定期审计**：定期检查和调整角色权限
4. **文档化**：记录权限配置的业务原因

### 5.2 批量分配建议
1. **分批处理**：大量用户分多次处理，避免一次性操作
2. **备份确认**：批量操作前确认用户列表
3. **测试优先**：先对少量用户测试，确认无误后批量执行
4. **及时通知**：角色变更后通知相关用户

### 5.3 权限检查规范

## 七、常见问题

### Q1: 如何为新角色添加权限？
**A:** 通过"角色权限管理"界面，选择角色后勾选权限，点击保存。

### Q2: 批量分配角色后，用户需要重新登录吗？
**A:** 建议用户重新登录，或在代码中实现权限刷新功能。

### Q3: 如何新增自定义权限项？
**A:** 在`sys_permission`表中插入新权限记录，并在`PermissionCode`枚举中添加对应项。

### Q4: Admin权限可以被撤销吗？
**A:** 不可以。系统管理员始终拥有所有权限，这是系统安全机制。

### Q5: 批量分配失败怎么办?
**A:** 系统会显示成功和失败数量。失败通常是由于数据库约束，检查日志定位问题。
