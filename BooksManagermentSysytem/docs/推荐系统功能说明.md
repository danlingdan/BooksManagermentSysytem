# 图书推荐系统功能说明

## 一、系统概述

图书推荐系统是图书管理系统的智能扩展模块，基于用户借阅行为和图书内容特征，为读者提供个性化的图书推荐服务。系统采用多种推荐算法相结合的方式，实现了三大核心推荐功能。

### 1.1 功能架构

```
┌─────────────────────────────────────────────────────────────┐
│                    RecommendationFacade                      │
│                      (统一API入口)                           │
├─────────────────┬─────────────────┬─────────────────────────┤
│  TrendingService │ ContentBased   │  PersonalizedService    │
│    热门榜服务    │   Service      │     个性化推荐服务       │
│                 │  相似书推荐服务  │                         │

│              (借阅记录、书目信息、用户数据)                   │
└─────────────────────────────────────────────────────────────┘
```

## 二、核心功能详解

### 2.1 全站热门榜 (Trending/Popular)

#### 功能描述
统计最近7天或30天内借阅量最高、增长最快的图书，生成全站热门排行榜。

#### 算法原理

```
热门分数 = 借阅量分数 × (1 - 增长率权重) + 增长率分数 × 增长率权重

其中：
- 借阅量分数 = 当前借阅量 / 最大借阅量（归一化到0-1）
- 增长率 = (本期借阅量 - 上期借阅量) / 上期借阅量
- 增长率分数 = (增长率 + 1) / 2（归一化到0-1）
- 增长率权重：7天榜为0.3，30天榜为0.2
```

#### API使用

```csharp
var recommendation = new RecommendationFacade();

// 获取本周热门榜（默认Top20）
var weeklyTrending = recommendation.GetWeeklyTrending();

// 获取本月热门榜
var monthlyTrending = recommendation.GetMonthlyTrending(topN: 30);

// 自定义配置
var customTrending = recommendation.GetTrending(new TrendingConfig
{
    Days = 14,                    // 统计14天
    TopN = 50,                    // 返回50本
    ConsiderGrowthRate = true,    // 考虑增长率
    GrowthRateWeight = 0.25,      // 增长率权重25%
    CategoryFilter = "TP"         // 只看计算机类
});
```

#### 返回数据示例

```json
{
  "BibliographyId": 1001,
  "BookName": "深入理解计算机系统",
  "Authors": "Randal E. Bryant",
  "CategoryName": "计算机科学",
  "BorrowCount": 156,
  "GrowthRate": 0.35,
  "Score": 0.92,
  "Reason": "本周热门第1名，借阅量持续上涨"
}
```

### 2.2 相似书推荐 (Similar Books)

#### 功能描述
当用户浏览或借阅某本书时，推荐与该书相似的其他图书。采用多维度相似性计算。

#### 算法原理

**综合相似度计算**：

| 维度 | 权重 | 说明 |
|------|------|------|
| 协同过滤 | 0.5 | 借过此书的人还借了什么 |
| 同作者 | 0.3 | 同一作者的其他作品 |
| 同分类 | 0.2 | 同分类下的热门图书 |

```
最终相似度 = Σ(各维度分数 × 权重)
```

#### API使用

```csharp
var recommendation = new RecommendationFacade();

// 综合相似书推荐（推荐）
var similarBooks = recommendation.GetSimilarBooks(bibliographyId: 1001);

// 借过此书的人还借了...
var alsoBorrowed = recommendation.GetAlsoBorrowed(bibliographyId: 1001);

// 同作者其他作品
var sameAuthor = recommendation.GetSameAuthorBooks(bibliographyId: 1001);

// 同分类热门书
var sameCategory = recommendation.GetSameCategoryBooks(bibliographyId: 1001);
```

#### 协同过滤SQL核心逻辑

```sql
-- 借过书A的人还借了什么书
SELECT b.bibliography_id, b.bibliography_name, COUNT(*) AS co_borrow_count
FROM book_borrow bb1
INNER JOIN book_item bi1 ON bb1.book_id = bi1.item_barcode
INNER JOIN book_borrow bb2 ON bb2.card_id = bb1.card_id 
    AND bb2.book_id != bb1.book_id
INNER JOIN book_item bi2 ON bb2.book_id = bi2.item_barcode
INNER JOIN bibliography b ON b.bibliography_id = bi2.bibliography_id
WHERE bi1.bibliography_id = @bookId
GROUP BY b.bibliography_id, b.bibliography_name
ORDER BY co_borrow_count DESC
```

### 2.3 个性化推荐 (For You)

#### 功能描述
根据读者的历史借阅行为，分析其阅读偏好，推荐可能感兴趣的图书。

#### 算法原理

**Step 1: 寻找相似用户**
```sql
-- 基于共同借阅的用户相似度
相似度 = 共同借阅书目数 / 目标用户总借阅数
```

**Step 2: 推荐相似用户借过的书**
```
优先推荐被更多相似用户借阅过的书籍
排除用户已借阅过的书籍
```

**Step 3: 补充基于分类偏好的推荐**
```
分析用户借阅的图书分类分布
推荐偏好分类中的热门图书
```

#### API使用

```csharp
var recommendation = new RecommendationFacade();

// 基础个性化推荐
var forYou = recommendation.GetForYou(cardId: "R001");

// 自定义配置
var customForYou = recommendation.GetForYou("R001", new PersonalizedConfig
{
    TopN = 15,                      // 返回15本
    SimilarUserCount = 30,          // 参考30个相似用户
    HistoryDays = 365,              // 分析1年的历史
    ExcludeBorrowed = true,         // 排除已借阅的书
    MinSimilarityThreshold = 0.15   // 最低相似度阈值
});

// 检查是否有足够历史数据
bool hasHistory = recommendation.HasSufficientHistory("R001", minBorrowCount: 3);

// 获取用户画像
var profile = recommendation.GetUserProfile("R001");
```

#### 用户画像数据结构


## 七、预计算相似度矩阵

### 7.1 功能概述

预计算相似度矩阵是推荐系统的性能优化功能，通过离线计算图书间的相似度并存储到数据库，大幅提升在线推荐查询速度。

### 7.2 相似度类型

| 类型 | 枚举值 | 算法 | 适用场景 |
|------|--------|------|----------|
| 内容相似度 | `ContentBased (1)` | 分类 + 作者匹配 | 新书、冷启动 |
| 协同过滤 | `Collaborative (2)` | Jaccard相似度 | 热门书籍 |
| 混合相似度 | `Hybrid (3)` | 加权综合 | **推荐使用** |

### 7.3 算法原理

#### 协同过滤相似度（Jaccard）
```
Jaccard(A, B) = |借过A的用户 ∩ 借过B的用户| / |借过A的用户 ∪ 借过B的用户|
```

#### 内容相似度
```
ContentSimilarity = CategoryScore × 0.4 + AuthorScore × 0.6

CategoryScore = 1 (同分类) 或 0 (不同分类)
AuthorScore = Jaccard(A的作者集合, B的作者集合)
```

#### 混合相似度
```
HybridScore = CollaborativeScore × 0.6 + ContentScore × 0.4
```

### 7.4 API使用

```csharp
var recommendation = new RecommendationFacade();

// 计算协同过滤相似度
var collabResult = recommendation.CalculateCollaborativeSimilarity(
    minBorrowers: 2,        // 最少借阅人数
    topSimilar: 20,         // 每本书保留Top20相似书
    minSimilarity: 0.05     // 最低相似度阈值
);

// 计算内容相似度
var contentResult = recommendation.CalculateContentSimilarity(
    categoryWeight: 0.4,    // 分类权重
    authorWeight: 0.6,      // 作者权重
    topSimilar: 20,
    minSimilarity: 0.1
);

// 计算混合相似度（推荐）
var hybridResult = recommendation.CalculateHybridSimilarity(
    collaborativeWeight: 0.6,
    contentWeight: 0.4,
    topSimilar: 20,
    minSimilarity: 0.1
);

// 执行全量计算（三种类型）
var allResults = recommendation.CalculateAllSimilarities();
```

## 八、性能优化建议

### 8.1 当前优化措施

1. **内存缓存**：使用 `MemoryCache` 减少重复计算
2. **索引优化**：为关键查询创建覆盖索引
3. **分页查询**：TOP N 限制返回数量
4. **延迟加载**：按需加载用户画像
5. **预计算相似度**：离线计算相似度矩阵，加速在线查询

### 8.2 预计算效果对比

| 场景 | 实时计算 | 预计算 |
|------|----------|--------|
| 相似书查询延迟 | 200-500ms | **10-30ms** |
| 数据库压力 | 高（多表JOIN） | 低（单表查询） |
| 适用书目数 | < 1000 | **10000+** |

推荐系统默认使用与主系统相同的连接字符串，也可单独配置：

```csharp
// 使用默认连接
var recommendation = new RecommendationFacade();

// 使用自定义连接
var recommendation = new RecommendationFacade(
    "Data Source=myserver;Initial Catalog=LibraryDB;..."
);
```

## 十、常见问题

### Q1: 个性化推荐显示"没有足够的借阅历史"
**A**: 用户需要至少借阅3本书才能生成个性化推荐。可调整阈值：
```csharp
recommendation.HasSufficientHistory(cardId, minBorrowCount: 2);
```

### Q2: 热门榜数据不更新
**A**: 检查缓存是否过期，或手动清除缓存：
```csharp
recommendation.ClearTrendingCache();
```

### Q3: 相似书推荐结果为空
**A**: 可能原因：
- 该书没有其他读者借阅过（协同过滤无数据）
- 该书没有设置分类或作者信息
- 该书是新入库的，借阅记录少

### Q4: 推荐速度较慢
**A**: 优化建议：
1. 确保数据库索引已创建
2. 减少 `TopN` 返回数量
3. 检查数据库服务器性能
4. 考虑启用预计算相似度
